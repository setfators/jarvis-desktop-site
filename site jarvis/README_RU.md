# J.A.R.V.I.S Portal — публикация

Это готовая статическая версия сайта. Перед публикацией нужно добавить реальную сборку и ссылку на неё.

## 1. Подготовь файлы сайта
Загрузи содержимое этой папки в новый GitHub-репозиторий (например, `jarvis-desktop-site`).
Файл `index.html` должен находиться в корне репозитория. Не загружай в репозиторий личные данные, ключи или файлы настроек приложения.

## 2. Включи GitHub Pages
1. Открой репозиторий → **Settings** → **Pages**.
2. В **Build and deployment** выбери источник **GitHub Actions**.
3. Вкладка **Actions** покажет процесс Deploy J.A.R.V.I.S website. После успешного запуска ссылка появится в Settings → Pages.

## 3. Опубликуй установщик
1. Открой репозиторий → **Releases** → **Draft a new release**.
2. Создай тег версии, например `v0.1.0`.
3. Прикрепи к релизу проверенный `JARVIS_Setup.exe` (или архив приложения) и опубликуй релиз.
4. Скопируй прямую ссылку на скачивание файла (GitHub обычно показывает ссылку на asset вида `/releases/download/v0.1.0/JARVIS_Setup.exe`).
5. Открой `site-config.js` и заполни:
   - `version`: номер версии;
   - `status`: значение `"available"`;
   - `downloadUrl`: прямая ссылка на EXE;
   - `releaseNotes`: короткое описание обновления.
6. Сохрани файл и отправь изменения в ветку `main`. Сайт обновится автоматически.

## Важно
- Не указывай выдуманную ссылку: пока `downloadUrl` пустой, кнопка загрузки останется выключенной.
- GitHub Pages делает сайт общедоступным. Перед публикацией проверь, что в репозитории нет приватных данных.
- Для GitHub Free Pages доступен в публичных репозиториях. Проверь действующие условия своего аккаунта.
- Этот пакет содержит сайт и workflow публикации, но не содержит JARVIS.exe и не создаёт GitHub-репозиторий за тебя.
